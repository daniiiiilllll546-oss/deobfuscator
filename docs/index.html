The lift

Same method. Before and after.

static int total(int[] data, int n) {
  FlowFrame f = new FlowFrame(new Object[]{data, n}, 4);
  while (!f.done) switch (f.pc / 16) {
    case 0: __flow$3$0(f); break;
  }
  return FlowFrame.i(f.result);
}

static void __flow$3$0(FlowFrame f) {
  switch (f.pc) {
  case 0: f.push(Integer.valueOf(0), 1);          f.pc = 1; return;
  case 1: f.locals[2] = f.pop();                 f.pc = 2; return;
  case 2: f.push(Integer.valueOf(0), 1);          f.pc = 3; return;
  case 3: f.locals[3] = f.pop();                 f.pc = 4; return;
  case 4: f.push(f.locals[3], 1); f.push(f.locals[1], 1);
          f.pc = FlowFrame.i(f.pop()) <= FlowFrame.i(f.pop()) ? 9 : 5; return;
  case 5: f.push(f.locals[2], 1); f.push(f.locals[0], 1);
          f.push(f.locals[3], 1);                f.pc = 6; return;
  case 6: { int k = FlowFrame.i(f.pop()); int[] a = (int[]) f.pop();
            f.push(Integer.valueOf(a[k]), 1); }           f.pc = 7; return;
  case 7: f.push(Integer.valueOf(FlowFrame.i(f.pop()) + FlowFrame.i(f.pop())), 1);
          f.locals[2] = f.pop();                 f.pc = 8; return;
  case 8: f.locals[3] = Integer.valueOf(FlowFrame.i(f.locals[3]) + 1); f.pc = 4; return;
  case 9: f.result = f.locals[2]; f.done = true; return;
  }
}
static int total(int[] data, int n) {
  int sum = 0;
  for (int i = 0; i < n; i++)
    sum += data[i];
  return sum;
}

Methods it can't model stay in interpreter form, still correct. Some lifted methods are too tangled for either decompiler and show as bytecode; the report counts them. Verified means well-formed, not proven identical.

How it works

The VM stack is the real stack. Lifting is mostly deletion.

The protector turns each method into a switch(pc) interpreter, one original instruction per case. Its operand stack mirrors the JVM's one to one, so the instruction survives once the wrapping goes.

f.push(Integer.valueOf(x), 1);
f.locals[2] = f.pop();
FlowFrame.i(a) + FlowFrame.i(b)
f.pc = 8; return;
// push · pop · pc · box: gone

01Strip

Drop push, pop, pc writes, done flags and the boxing the protector added as type hints.

f.locals[n] → slot 200+2n
f.pc = 4 → GOTO L4
rearrange(3) → DUP_X1
construct(T) → NEW · DUP · INVOKESPECIAL
done = true → IRETURN

02Re-thread

VM locals become real slots, pc jumps become labels, stack shuffles become real ops. Try/catch ranges rebuilt.

$ deflow.Verify plugin.deflow.jar
verified OK: every class
missing deps: add with --cp
VERIFY ERRORS: 0
// failure → roll back method

03Verify

ASM rebuilds stack-map frames, the JVM verifier loads every class. Anything that fails rolls back.
